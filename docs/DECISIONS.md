# Journal des décisions techniques

| Date | Décision | Raison | Alternatives écartées |
|---|---|---|---|
| 2026-10-29 | Moteur Godot 4.3+, GDScript à typage statique | Moteur libre, léger, adapté aux interfaces riches ; le typage limite les erreurs | Unity, C# généralisé |
| 2026-10-29 | Données de jeu en JSON dans `data/`, surchargeables par `user://mods/` | Moddable sans toucher au code | Données en dur, `.tres` uniquement |
| 2026-10-29 | Simulation séparée de l'affichage (`RefCounted` + commandes) | Sauvegardes simples, simulation déterministe, multijoueur possible plus tard | Logique dans les nœuds de scène |
| 2026-10-29 | Branches `main` / `develop` / branches de travail, versions SemVer `v0.N.0` par étape | Historique lisible, `main` toujours stable | Développement direct sur `main` |
| 2026-10-29 | Version minimale Godot 4.7 (au lieu de 4.3) | Le projet est développé et testé avec 4.7.2 ; GUT 9.7 cible 4.7 | Rester compatible 4.3 sans pouvoir le tester |
| 2026-10-29 | Données regroupées par catégorie = dossier (`data/countries/*.json` → `countries`), fichiers fusionnés par identifiant | Un mod ou un DLC ajoute un fichier sans toucher aux existants | Un fichier unique par type, surcharge fichier par fichier |
| 2026-10-29 | Fusion des mods : objets fusionnés, tableaux remplacés, `null` supprime, `__replace` remplace un objet | Règles simples et prévisibles | Concaténation des tableaux (impossible de retirer un élément) |
| 2026-10-29 | Schémas maison (sous-ensemble de JSON Schema) avec `ref` pour les références entre catégories | Lisible par les moddeurs, détecte les identifiants inexistants | JSON Schema complet (lourd), pas de validation |
| 2026-10-29 | Traductions en CSV lues au démarrage (import Godot « keep ») plutôt qu'importées par l'éditeur | Les mods peuvent ajouter ou remplacer des textes | Import CSV natif de Godot (figé à l'export) |
| 2026-10-29 | Idéologies, régimes, terrains et ressources sont des catégories de données, référencées par identifiant | Extensibles par les mods, sans liste figée dans le code | Énumérations dans le code |
| 2026-10-29 | Autoload supplémentaire `SystemRegistry` (fournisseurs par clé, priorité) | Point d'extension pour remplacer des modules (militaire, IA…) par un DLC | Registre dans `GameState` (réinitialisé à chaque partie) |
| 2026-10-29 | État de partie dans une classe pure `SimState`, modifiée uniquement par des `Command` en file | Séparation simulation / affichage, déterminisme, sauvegardes | L'UI modifie l'état directement |
| 2026-10-29 | Mods utilisateur désactivés pour l'instant (`ModManager.USER_MODS_ENABLED = false`), mécanisme de fusion conservé | Pas de compatibilité mod à garantir pendant le développement ; la fusion sert aussi aux DLC | Supprimer tout le code mod |
| 2026-10-29 | Déclarations non typées traitées comme des erreurs (`untyped_declaration = 2`) | Rend le typage statique obligatoire | Simple avertissement |
| 2026-10-29 | Carte générée depuis Natural Earth (régions de premier niveau, ~4 600 provinces) par un outil Python versionné | Frontières réelles, domaine public, regénérable | Carte dessinée à la main, découpage plus grossier |
| 2026-10-29 | Populations des provinces issues de Wikidata (données de Wikipédia), estimation en secours | Chiffres réels et sourcés | Répartition estimée par surface et villes (trop imprécise) |
| 2026-10-29 | Image des provinces en 16384 × 8192, couleur = identifiant (`R + G × 256`) | Précision élevée ; le shader et le clic lisent l'id sans table de conversion, texture RG8 (~270 Mo) | Couleurs libres + table de correspondance (conversion pixel par pixel trop lente à cette taille) |
| 2026-10-29 | Images de carte dans Git LFS, hook `pre-push` étendu pour l'envoi LFS | Dépôt léger malgré les regénérations | Images directement dans Git |
| 2026-10-29 | Dépendances rattachées à leur État (Groenland → Danemark, Porto Rico → États-Unis…) ; Taïwan, Kosovo, Palestine, Chypre du Nord, Somaliland sont des pays | Fidèle à la situation de 2026, entités non reconnues jouables | Dépendances jouables |
| 2026-10-29 | Carte rendue par un seul rectangle plein écran : le shader calcule la position de carte de chaque pixel à partir de la caméra | Bouclage est-ouest gratuit, une seule texture de 16384 × 8192, aucun nœud par province | Sprite de carte dupliqué pour le bouclage, Camera2D |
| 2026-10-29 | Couleurs des provinces dans une texture de correspondance 256 × N (id → couleur) | Changer de mode de carte ne regénère qu'une petite texture | Recolorer l'image complète |
| 2026-10-29 | Raccourcis de déplacement en touches physiques | WASD et ZQSD fonctionnent selon la disposition du clavier | Touches logiques (inutilisables en AZERTY) |
| 2026-10-29 | Modes de carte décrits en données (type, dégradé, couleurs, ordre) et implémentés par 9 types réutilisables | Ajouter ou régler un mode sans toucher au code | Une classe codée par mode |
| 2026-10-29 | Contours lissés dans le shader (pondération bilinéaire des 4 pixels voisins), frontières par comparaison avec 4 voisins à distance fixe en pixels d'écran | Rendu net à tout zoom sans regénérer la carte ni la vectoriser ; ~3,5 ms GPU par image | Contours vectoriels précalculés, champ de distance |
| 2026-10-29 | Noms de pays : axe principal du plus grand territoire d'un seul tenant, parabole ajustée, courbe coupée à la partie située dans le pays | Suit la forme des pays sans données manuelles, se recalcule si les frontières changent | Positions de noms saisies à la main |
| 2026-10-29 | Zones maritimes dans la même image que les provinces, numérotées à leur suite, décrites dans `data/sea_zones/` | Un seul système de sélection et de voisinage pour terre et mer | Image séparée pour les mers |
| 2026-10-29 | Zones maritimes : mers nommées de Natural Earth, petites mers fusionnées (sauf mers stratégiques protégées), océans découpés en secteurs de ~2 millions de km² | Noms réels et taille de zone jouable pour le contrôle naval | Grille régulière, Voronoï sans noms |
| 2026-10-29 | Détroits et canaux comme liens entre deux zones maritimes, avec les provinces riveraines | Les détroits fins (Bosphore) ou les canaux n'existent pas à la résolution de l'image | Les dessiner dans l'image |
| 2026-10-29 | Clic simple = fiche du pays, double-clic = fiche de la province | Navigation à la manière des jeux de grande stratégie : le pays d'abord, le détail ensuite | Clic = province |
| 2026-10-29 | Fusions de régions configurables dans le générateur (Londres : 33 arrondissements → 1 province) ; secteurs d'océan de ~8 millions de km² | Découpage plus jouable, moins de micro-provinces et de zones maritimes | Découpage brut de Natural Earth |
| 2026-10-29 | Ordonnanceur dans `GameState` : un tick = une heure (commandes, date, systèmes par période, puis signaux) ; systèmes triés par priorité puis ordre d'ajout | Simulation déterministe, systèmes lents appelés seulement à leur période | Chaque système avec son propre minuteur |
| 2026-10-29 | Vitesses calquées sur HOI4 (secondes réelles par heure : 2 ; 0,5 ; 0,2 ; 0,1 ; sans limite), vitesse 3 par défaut, au plus 48 ticks par image et 8 ms de simulation en vitesse 5 | Rythme familier aux joueurs de HOI4 / CK3, jeu fluide en vitesse maximale | Vitesses maison (6 h à 20 jours par seconde) |
| 2026-10-29 | Raccourcis du temps en touches logiques (Espace, +, -) | Les touches + et - suivent le caractère imprimé, quelle que soit la disposition du clavier | Touches physiques |
| 2026-10-29 | Données chiffrées des pays tirées des tableaux de Wikipédia (FMI, ONU, IISS) par un outil versionné ; régimes et organisations saisis à la main | Chiffres sourcés et regénérables ; la situation politique exacte au 1er janvier 2026 est plus fiable saisie à la main | Wikidata (dates et qualifications inégales), saisie entièrement manuelle |
| 2026-10-30 | Champs politiques des pays (dirigeants, partis, culture, idéologie) dans `data/countries/politics.json` (écrit à la main) et `politics_generated.json` (généré), fusionnés avec `countries.json` par identifiant | Chaque outil possède ses fichiers ; la saisie manuelle et la génération ne s'écrasent pas | Un seul `countries.json` modifié par plusieurs outils |
| 2026-10-30 | Outil de génération des dirigeants écrit en GDScript (lancé en mode headless) et réutilisant `NameGenerator` | Un seul algorithme pour l'outil et pour les personnages créés en cours de partie | Outil Python dupliquant l'algorithme |
| 2026-10-30 | Noms de partis complets, classés par groupe d'idéologie et par langue, avec groupes de repli | Pas de faute d'accord, noms crédibles, aucun parti réel | Modèles à trous « {nom} {adjectif} » |
| 2026-10-30 | Partis des pays à alphabet non latin nommés en FR / EN ; langue locale pour les autres | Lisible pour le joueur, crédible localement | Translittération |
| 2026-10-30 | Un chef de l'État commun peut diriger plusieurs pays (royaumes du Commonwealth, coprince d'Andorre) : référence au personnage de son pays | Fidèle à la situation réelle | Un gouverneur général fictif par royaume |
| 2026-10-30 | Profondeur des partis à l'étape 3 limitée au pouvoir et à la coalition | L'opposition, les scores et les sondages arrivent avec la politique intérieure (étape 5) | Paysage politique complet dès l'étape 3 |
| 2026-10-30 | Drapeaux en SVG tirés de flag-icons (MIT), complétés par Wikimedia Commons pour les drapeaux absents ou en usage de fait (Afghanistan, Chypre du Nord, Somaliland), par un outil versionné | Drapeaux exacts, licences libres, regénérables ; Godot importe le SVG directement | Drapeaux dessinés à la main, PNG téléchargés |
| 2026-10-30 | Tous les drapeaux au format 4:3 (recadrés au centre, ou complétés par une couleur de fond si une inscription serait coupée), rendus en 320 × 240 avec mipmaps | Affichage homogène dans l'interface, net en petit, ~12 Mo de mémoire vidéo pour tous les drapeaux | Proportions officielles de chaque drapeau |
| 2026-10-30 | Chemin du drapeau par convention (`assets/flags/<TAG>.svg`), champ `flag` facultatif pour le remplacer ; repli sur la couleur du pays | Pas de données répétées 199 fois, un mod peut fournir son drapeau | Champ `flag` obligatoire dans `countries.json` |
| 2026-10-30 | Sélection du pays comme mode de l'écran de jeu (temps arrêté, panneaux sur la carte) | La carte n'est chargée qu'une fois ; « Jouer » démarre sans attente | Scène de sélection séparée avec sa propre carte |
| 2026-10-30 | Difficulté = log10 du PIB + ½ log10 des effectifs (avec plancher), moins le poids des défis, classée en 5 niveaux par des seuils de `defines.json` ; champ `difficulty` pour forcer un niveau | Cohérente pour 199 pays sans saisie, réglable, retouchable | Niveau saisi à la main pour chaque pays, simples rangs de puissance |
| 2026-10-30 | Défis de départ en données (`data/challenges/`) : génériques avec une règle, ou écrits pour un pays ; un pays qui a sa liste n'hérite pas des défis génériques | Textes précis pour les pays majeurs, couverture automatique des autres | Défis tous générés, ou tous écrits à la main |
| 2026-10-30 | Champs de sélection (`challenges`, `difficulty`, `limited_recognition`) dans `data/countries/selection.json`, fusionné avec les pays | Même principe que `politics.json` : chaque source a son fichier | Champs ajoutés dans `countries.json` |
| 2026-10-30 | Seuls Chypre du Nord et le Somaliland sont réservés au mode avancé ; Taïwan, le Kosovo et la Palestine restent toujours jouables | Ils sont reconnus par de nombreux États | Toutes les entités contestées en mode avancé |
| 2026-10-30 | État de partie en classes typées (`SimState.countries` → `CountryState` → `EconomyState`, `SimState.currencies` → `CurrencyState`) créées par `WorldSetup` depuis les données | Typage strict, tests simples, sauvegarde sérialisable ; les données JSON ne bougent plus pendant la partie | Copie des dictionnaires JSON modifiée en place |
| 2026-10-30 | Données économiques lues dans les pages Wikipédia telles qu'elles étaient le 1er janvier 2026 (révision à la date) | Chiffres cohérents avec la date de départ, regénérables à l'identique | Version actuelle des pages |
| 2026-10-30 | Modèle calé à l'équilibre au départ : taux neutres, écart de note et taux de la dette propres à chaque pays reprennent la situation réelle | La partie ne dérive pas dès le premier mois ; seules les décisions et les chocs font bouger l'économie | Paramètres communs à tous les pays |
| 2026-10-30 | Dette séparée en monnaie locale et en devises | Sans cela, l'inflation effaçait la dette des pays émergents (Argentine : -30 points par an) | Dette entièrement locale |
| 2026-10-30 | Banque centrale sous contrôle du gouvernement : le joueur fixe le taux, qui ne bouge plus sans lui ; les monnaies ancrées suivent leur ancre ; une union monétaire n'a qu'une banque centrale | Fidèle aux institutions réelles, décision forte pour le joueur | Taux toujours automatique |
| 2026-10-30 | Solde budgétaire primaire réel de 2025 figé jusqu'au budget détaillé (4b) | La dette évolue de façon crédible dès la 4a | Dette figée |
| 2026-10-30 | Commandes appliquées tout de suite quand le jeu est en pause | Le joueur voit l'effet de sa décision sans relancer le temps ; l'ordre des commandes reste déterministe | Attendre le tick suivant |
| 2026-10-30 | Impôts et postes de dépense décrits en données avec leurs effets par point de taux ou de PIB, mesurés par rapport au budget de départ | Le budget de départ est neutre ; équilibrer ou ajouter une ligne sans toucher au code | Effets codés en dur |
| 2026-10-30 | Effets non économiques (groupes sociaux, stabilité, recherche, armée, influence) calculés et affichés dès la 4b, appliqués par leurs systèmes aux étapes 5 à 8 | Le joueur voit déjà les conséquences de son budget | Les ajouter étape par étape |
| 2026-10-30 | Recettes d'un impôt = taux × recettes par point (calées au départ) × base qui se dérobe quand le taux monte | Retrouve les recettes réelles et donne une courbe de Laffer simple | Assiettes fiscales détaillées |
| 2026-10-30 | Dépenses en % du PIB, ajustées au départ pour retrouver le solde réel | Les dépenses suivent l'économie sans micro-gestion ; pas de dérive au premier mois | Montants en milliards |
| 2026-10-30 | Budget calculé par `BudgetSystem` (priorité -10) avant l'économie, qui lit le solde primaire et les effets | Systèmes séparés et ordre déterministe | Budget dans `EconomySystem` |
| 2026-10-30 | Règle provisoire de l'IA : solde primaire visé = solde de départ + 0,1 point par point de dette gagné, ajusté d'au plus 1 point de PIB par an | Corrige les dérives (Argentine, Liban, Ukraine) avant l'IA de l'étape 12 | Budget figé |
| 2026-10-31 | Étape 4c découpée en 4c1 (ressources, marché mondial, chaînes d'approvisionnement) et 4c2 (accords, douanes par partenaire, embargos, dépendances) | Sous-étapes de taille raisonnable, validées séparément | Une seule sous-étape |
| 2026-10-31 | Un marché mondial unique par ressource, prix d'équilibre recherché par dichotomie chaque mois ; le prix du marché s'en rapproche à moitié | Léger pour 199 pays, chocs crédibles, pas de matrice d'échanges à caler | Flux bilatéraux complets |
| 2026-10-31 | Effets des ressources mesurés par rapport à une situation normale (prix de départ, rien de bloqué) | Neutres au départ, seuls les chocs et les tendances jouent | Effets absolus |
| 2026-10-31 | Fermeture d'un détroit : les exportations déclarées pour ce détroit (`data/straits/trade.json`) ne trouvent plus preneur | Simple, montre les dépendances réelles (Ormuz, Bosphore pour le blé) | Routes maritimes calculées |
| 2026-10-31 | Pénurie = part des besoins abandonnée à cause du prix ; les secteurs déclarent leurs ressources en données | Chaînes d'approvisionnement lisibles et réglables, réutilisables par la production militaire (étape 7) | Stocks par usine |
| 2026-10-31 | Eau non échangée : indice de stress hydrique affiché, effets laissés au climat (étape 10) | Pas de marché mondial de l'eau ; éviter un frein constant dès le départ | Pénalité agricole immédiate |
| 2026-10-31 | Aucun embargo au départ : les sanctions réelles arriveront avec la diplomatie (étape 6) | Choix de design | Embargos réels dès 2026 |
| 2026-10-31 | Flux de commerce précalculés par l'outil (modèle gravitaire, ajustement proportionnel itératif, facteurs saisis pour quelques paires) et limités aux 60 premiers partenaires de chaque pays | Mise en place en 0,3 s au lieu de 3,6 s ; partenaires proches de la réalité | Calcul au lancement de la partie |
| 2026-10-31 | Droit effectif = droit habituel du budget (supprimé dans un accord, divisé par deux dans un accord partiel) + surtaxe ; embargo = droit prohibitif. | 2026-10-31 | Droits effectifs recalculés seulement quand ils peuvent changer (commande, droit habituel modifié) ; chaque mois, seules les paires modifiées sont parcourues | Le commerce coûte moins de 2 ms par mois | Recalcul complet chaque mois |
